# kpipe v5 usage

Hard rules, token-saving practices and the delivery flow are governed by houdini-mcp-conventions; **paths and naming are governed by this skill**. Finished kpipe work (code, comments, help, labels) is **English only**; use Chinese only in conversation.

- Code: `<HOUDINI>/pipeline/python/kpipe/` (config, project, scene, create_ui, open_ui, shot_picker, ui, cache, flipbook, tops, shot_value); `_parked/` holds the old batch/tops code, which is no longer used.
- HDAs: `pipeline/otls/kpipe_scene_manager.hda` (`kpipe::scene_manager::1.0`, generated by `scene.build_hda()`) and `pipeline/otls/kpipe_shot_value.hda` (`kpipe::shot_value::1.0`, generated by `shot_value.build_hda()`).
- Shelf "KPipe": Create, Open Work File, Scene Manager, Save Version, Snapshot, Shot Wedge, Shot Value, Reload KPipe. `toolbar/kpipe.shelf` is read-only (to stop Houdini from rewriting it); clear the read-only flag before editing.
- **Running code inside the user's open Houdini** (when the fxhoudini tools are unavailable): write the code into a `.py` file, then run `<python> <HOUDINI>/pipeline/tools/hou_exec.py <file.py>` (over port 8100; the result is in `data.stdout`). After changing kpipe, reload it this way (or ask the user to click Reload KPipe).

## Structure
```
<HOUDINI>/projects/<project>/        Test projects live in <HOUDINI>/mcp_workflow_playground/<project>/
├── project.json    {"created": "...", "shots": {"GRS_0010": {"start": 1001, "end": 1020}},
│                                     "assets": {"fxGrass": {"start": 1, "end": 100}}}
├── shot/<SEQ>/<SHOT>/            ← var_dir (shot)
│   ├── scenes/     GRS_0010_v001_artist.hip  GRS_0010_v002_mcp.hip   ← var_scenes
│   ├── cache/      <node>/v1/<node>_v1.$F4.bgeo.sc                 ← var_cache
│   ├── playblast/  flipbook output                                 ← var_playblast
│   ├── assets/     assets used by this shot                        ← var_assets
│   └── render/     render output                                   ← var_render
└── asset/<category>/<asset>/     ← var_dir (asset), same subfolders
```
- Project code: starts with a lowercase letter, e.g. `grass`. Shots are `SEQ_NNNN`: three uppercase letters plus four digits, step 10. An asset code is a lowercase category plus a capitalized name (`fxGrass`, `envForest`); the category is read from the prefix, with defaults in `config.ASSET_CATEGORIES` (fx/env/model/char/prop), and new ones can be added. Shots and assets both record only frame ranges and are used identically (below, "shot" includes assets).
- hip name: `<code>_vNNN_<artist>.hip`, **no description suffix** (removed in round 5). **Files saved by MCP use artist=`mcp`** (`config.MCP_ARTIST`).
- Old projects from before round 5 (source/preview layout, suffixed hip names, e.g. supertest, ktest) are not compatible; the user said they will be deleted in the next version.

## API
```python
from kpipe import config, project, scene, cache, flipbook, tops
project.new_project("grass", playground=False)
project.new_shot("grass", "GRS_0010", 1001, 1020)        # omit the range to reuse the previous shot's
project.new_asset("grass", project.asset_code("fx", "grass"), 1, 100)   # fxGrass
project.items("grass")                                    # shots (sorted) + assets (by category)
project.item_dir("grass", "fxGrass"); project.scenes_dir("grass", "GRS_0010")
project.next_shot_number("grass", "GRS")                  # next number (step 10)
project.set_range("grass", "GRS_0010", 1001, 1030)        # works for shots and assets
hip = project.new_work_file("grass", "GRS_0010", config.MCP_ARTIST, empty=False)  # save current scene as v001 + set Scene Manager
project.save_version(artist=config.MCP_ARTIST)            # no description
project.hip_versions("grass", "GRS_0010")             # [dict(ver, artist, mtime, path)], newest first
project.latest_hip("grass", "GRS_0010"); project.open_hip(path)  # errors on unsaved changes; pass force=True only with the user's consent
scene.set_shot("GRS_0020")                                # switch shot, returns var_dir
```
- Projects, shots and work files that already exist raise `FileExistsError`; for a work file, the error message is the path to the latest hip. Do not create an empty version instead.
- `empty=True` clears the current scene: ask the user first.

## Scene Manager (/obj/scene_manager)
- Top of the panel (not inside a folder): **Project** (dropdown) + **Update Context** button (`scene.update_context()`: clears the manifest cache, re-reads project.json, rebuilds the lists, and syncs ranges/playbar/wedges); **Current Shot** (parameter `shot`, a plain short text field, can be typed or Copy Parameter'd) + **Pick Shot...** (`shot_picker.select(n)`, a single-select dialog: two groups, Shots (by SEQ) and Assets (by category), listing `scene.selectable_shots()` = Wedge Shots, or all shots when that is empty; double-click or OK switches, Cancel changes nothing). Typing the wrong case is corrected to the registered spelling (`aaa_0010`→`AAA_0010`, `FXGRASS`→`fxGrass`); a shot that does not exist **snaps back** to the previous valid shot (hidden parameter `last_shot`), with a status-bar warning. Projects, shots and assets can only be created from the Create window (`create_ui.show()`): choose Type Shot / Asset; Shot = Sequence dropdown (you can type three uppercase letters) + Number (suggests the next number, step 10) → `RGS_0050`; Asset = Category dropdown (defaults + ones already used; you can type a lowercase category) + Name (`Grass`) → `fxGrass`.
- **Layout**: each row uses `scene.row(name, *pts, spacers=N)`, and N empty Labels after the field + button consume the extra width, so text boxes stay short (Houdini cannot set widths directly). var_dir, the five sub-path variables, and Shot Value's Match stay long.
- **Callbacks must use the tuple name**: `_ON_CHANGE` passes `kwargs['parm'].tuple().name()`. When a two-component Int parameter is edited in the UI, `parm_name` is the component name such as `project_range1`; branching on it goes down the wrong path and snaps the value back (the reason Range could not be edited in round 3). Do not use `kwargs['parm_tuple']`: when a string parameter is typed in the UI that key is absent from kwargs and raises KeyError (fixed 2026-11-05). Tests must execute the real callback string, not pass `"project_range"` directly.
- **Switching shots resets simulations**: Shot Value's Result is a Python expression, and switching shots does not mark downstream nodes as changed, so DOPs keep using the previous shot's cache. Therefore `on_change` calls `scene.reset_sims()` when the project or shot changes, pressing every `resimulate` button below /obj. Previewing a TOP work item does not change DOP simulation: DOP evaluation has no work-item context, only parameters and SOPs follow it.
- The node comment shows the active shot as `project / SHOT | start-end`, with `[work item]` appended when previewing a work item (QTimer refreshes every 0.5 s, `scene.start_watch()`; started automatically by the HDA's OnLoaded).
- Context: **Project Range** (`project_range1/2`, written back to project.json when changed), **Custom Range** (`custom_range1/2`, plain numbers; typed values are **remembered per shot in the hip**: hidden parameter `custom_ranges` = JSON `{code: [start, end]}`, read with `scene.custom_ranges(n)`; not recorded when equal to Project Range. Switching away and back restores it; shots with no record follow Project Range; changing Project Range does not overwrite recorded values; the **Reset** button on the same row (`scene.reset_custom_range()`) deletes this shot's record; changing projects clears them all. **Do not use ch() links**: Houdini writes sets on a referencing parameter back to the referenced parameter), Artist; buttons Open Latest, Save Version, Sync Playbar (pushes Custom Range to the playbar). The current shot's var_start/var_end use Custom Range live; a work item uses the Custom Range remembered for its shot, falling back to Project Range (TOP wedge cache frame counts follow the same rule). Save Version saves on click (no input dialog) and then shows a Saved window. API: `scene.set_custom_range(s, e)`.
- Wedge folder: **Wedge Shots** (`wedge_shots`, free text, space/comma separated; the callback normalizes to registered spellings, project order, and drops unknown ones; shots and assets can be mixed) + Pick Shots...; **Enable Slice** toggle; **Slice List** (`slice_shots`, must be a subset of Wedge Shots; disabled when Enable Slice is off) + Pick Slice...; **Sent to Wedge** (`wedge_list`, a read-only status line, a plain string that reverts if edited); Sync Wedge (safety net).
- Shots sent into the shot wedge (`tops.selected_shots()`): Enable Slice on → Slice List; off → Wedge Shots; when empty, both fall back to the current shot (displayed as `(current shot)`). Any change automatically calls `tops.sync_wedges()`; changing projects clears both lists.
- `shot_picker.show(n, "wedge_shots"|"slice_shots")`: two groups, Shots / Assets; Add to List / Replace List / Clear List; Slice mode lists only Wedge Shots.
- Status lines (Sent to Wedge, Source) are written by `refresh_status()` as plain values (not expressions, so they match the other parameters' color); expressions left over in old hips are removed automatically.
- Variables: var_shot, var_dir, var_scenes, var_cache, var_playblast, var_assets, var_render (= var_dir + "/subfolder"), var_start, var_end are **live Python expressions for the active shot**: when a work item carrying a `shot` attribute is selected in TOP they use it (`pdg.EvaluationContext.workItemDep()`, refreshed automatically when another work item is selected), otherwise they use the Current Shot parameter. Current Shot and the playbar do not follow the work item. The Source line shows where the value came from; the Clear Work Item button (`scene.clear_work_item()`: all topnets `deselectWorkItem()` + `setGlobalWorkItem(None, True)`; deselect alone is not enough, the global work item stays behind).
- Other nodes reference them like this: `` `chs("/obj/scene_manager/var_cache")` ``, `ch("/obj/scene_manager/var_start")`.
- In Python, `parm.set()` does not fire callbacks. After changing a parameter call `scene.on_change(n, "<parm name>")`, or just use `scene.set_shot()`. To change lists use `scene.pick_shots(shots, "add"|"replace"|"clear", n, target="wedge_shots"|"slice_shots")`.

## Open Work File (shelf, `open_ui.show()`)
- Project dropdown + Artist + Only mine; a search box on the left (case-insensitive substring, `open_ui.visible_codes`) + tree (`shot_picker._fill`: Shots by SEQ, Assets by category); a version table on the right (Version / Artist / Modified, newest first, latest selected by default; Only mine lists only that artist's versions, `open_ui.filter_versions`); the path relative to the project is shown below.
- Double-click or Open: first `ui._confirm_unsaved()` (Save / Discard / Cancel), then `project.open_hip(path, force=True)`, then close the window. The last opened project + shot are stored in `QSettings("kpipe", "open_work_file")`, and the window opens there next time.
- Do not actually open files in the user's live Houdini on their behalf (it would replace their scene); test with hython or screenshots (`widget.grab()`).

## Shot Value SOP (`kpipe::shot_value::1.0`)
- Gives per-shot values. **No inputs**; outputs empty geometry plus one detail attribute. Tab menu KPipe category (the HDA's Tools.shelf, `soptoolutils.genericTool`); the shelf "Shot Value" calls `shot_value.create_here()`: creates the node at the mouse position in the current SOP network, and if it is not in a SOP network shows a status-bar message and creates nothing (no more automatic geo). API: `shot_value.create(sop_net)`. The HDA is generated by `shot_value.build_hda()` (`pipeline/otls/kpipe_shot_value.hda`, containing a Python SOP that calls `shot_value.cook`).
- Parameters: Attribute (attribute name, default `value`), Type (float/int/string/vector, decides which `default_*`/`value_*#`/`result_*` group is used), **Match** (default `` `chs("/obj/scene_manager/var_shot")` ``, can be any parameter reference or a literal), Default Value, **Result** (live Python expression, Copy Parameter can reference it), Rules (multiparm: Enable, Pattern, Value; use Houdini's built-in multiparm controls to reorder).
- Rules are evaluated top to bottom; the first enabled rule whose Pattern matches wins. Patterns are space-separated and support `*`/`?` (fnmatch, case-sensitive). If none match, Default is used.

## Rebuilding the HDA
- When the HDA is already installed from the same path, both `build_hda()` functions **update the definition in place** (`installed_definition()` + `interface()`: new parm template groups, sections) without uninstalling. Uninstalling resets every existing node's parameter values to defaults (this is why the user's Project/Shot kept going blank before), and the Console reports "Unable to find dialog script".
- Only the first install, or a path change, does a full rebuild; then `save_instances()` / `restore_instances()` (`parmsAsData` / `setParmsFromData`) preserve existing nodes' values.
- In-place updates do not change the Python SOP inside Shot Value; to change internal nodes, delete the HDA file and rebuild completely.

## Caching and TOP per-shot wedge
- `cache.create_cache(sop)`: creates a Labs File Cache with basedir `` `chs(var_cache)` `` and f1/f2 referencing var_start / var_end. `cache.estimate(node)` cooks test frames and extrapolates (hard rule: measure first, ask the user before anything over 2 GB).
- The shelf "Shot Wedge" uses the selected Labs File Cache; if none is selected and the scene has exactly one kpipe cache (`cache.tagged_caches()`), it uses that automatically.
- `tops.build_shot_wedge(cache_node)` → `/obj/shot_wedge`:
  - `wedge_shots` (Wedge): String attribute `shot`, Value List = the shots sent by Scene Manager (Slice List or Wedge Shots, `tops.selected_shots()`, written by `sync_wedges()` into every Wedge whose name1=shot and whose Target points at scene_manager/shot — do not edit by hand), Target Parameter `/obj/scene_manager/shot`;
  - `cache_shots` (ROP Fetch): ROP Path `<cache>/render`, Frame Generation set to ROP Node Configuration;
  - a readme sticky note is included. Save the hip before cooking (ROP Fetch cooks the save file in the background). Verified: every shot caches into its own cache/, and the frame count equals its own frame range.
- Note: ROP Fetch defaults to Single Frame and would cook only 1 frame; it must be set to ROP Node Configuration.

## Snapshot / flipbook
- `flipbook.snapshot()`: capture the viewport's current frame → `%TEMP%/kpipe_snapshot.png` → clipboard.
- `flipbook.deliver()`: png sequence + mp4 + key-frame contact sheet, written to `<var_dir>/playblast` (var_playblast). If MPlay is open, call `flipbook.cleanup()` first.
